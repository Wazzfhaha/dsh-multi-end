# 兼容性与升级检查

## 当前适配范围

插件 0.0.8；DSH 适配基线 0.1.7-rc.1。会话控制流契约、登录重定向与 Web Gateway 分派路径已按 0.1.7 的真实行为修正。WSL 主后端连接 Agent Box 的原生侧栏、搜索、历史和工作区登记已实机验收。Windows、macOS 远端及多客户端并发实机验证暂缓，不能宣传“所有平台已验证”。

| 功能 | 实现及验证范围 |
| --- | --- |
| 原生会话、历史、流式输出 | gateway 按所属后端路由；此前原生浏览器验收通过 |
| 发送、取消 | 接入；本地模拟协议测试覆盖。当前轮没有对真实后端发送模型请求或取消已有任务 |
| 改名、归档、工作区内排序 | 接入；本轮在专用空会话上真实验收 |
| 创建工作区和会话 | 在“多端管理”中浏览或新建目录，再通过所属后端登记工作区。系统弹窗模式自动回退到 SSH SFTP；不修改远端 DSH 配置。新建会话本轮未实测 |
| 分叉 | 转发原生 fork 接口并转换返回会话 ID；未在本轮对真实有历史会话验收 |
| 队列操作、附件读取与上传、会话 skills、文件引用 | 已接入显式路由与身份隔离测试；完整真实 UI 流程仍待验收。传输响应及流帧当前限制 4 MiB |
| 工具审批、用户提问 | 未接入。上游使用可回传结果的远程事件通道，不是普通会话 RPC；须到所属后端界面处理 |
| 第三方卡片和动态插件运行 | 未接入；不能因为原生界面渲染了卡片就认为其交互已支持 |
| 已归档会话 | 管理页隐藏；0.1.7 原生取消归档接口已接入 |
| 置顶与侧栏搜索 | 0.1.7 的 pinned 工作区状态、pin/unpin 与 session/search 已聚合；远端会话搜索及打开历史已实机验收，置顶未在本轮实测 |
| 远端文件侧栏 | 未接入；已识别远端文件 scope，拒绝向主后端回落 |
| 跨机器移动/复制 | 不支持；不同后端身份组合拒绝执行 |
| 重连 | 有限重试、保留身份、原生重新订阅；不会自动重发变更请求 |
| 主后端重启 | 自动读取登录信息连接过的主机自动恢复；手动登录链接不保存 |
| 全局设置、插件与 skills 同步 | 不同步，主后端仍负责全局界面 |

## 跨平台审计（2026-09-24）

结论：这是面向多平台的 DSH Web 插件，不能宣称兼容所有 0.1.7-rc.1 安装方式或所有原生交互。版本相同并不保证启用了相同的服务、目录选择器和客户端载入器。

| 范围 | 代码支持与限制 | 实机证据 |
| --- | --- | --- |
| WSL/Linux 主后端 → Linux 远端 | OpenSSH 隧道、原生 Web Gateway；远端无需安装本插件 | 已验证连接、重启恢复、侧栏、搜索、历史及工作区登记/移除 |
| Windows 主后端 | 使用系统 OpenSSH 路径；需安装 Windows OpenSSH Client，只有其他位置的 ssh.exe 不够 | 尚未完整实测 |
| macOS 主后端 | 从 PATH 调用 ssh，使用当前用户的 SSH 配置 | 尚未实测 |
| Windows/macOS 远端 | 手动提供 DSH loopback HTTP 登录链接，通过 SSH 转发；不依赖远端 Python | 尚未实测 |
| 自动读取登录信息 | 仅 Linux；需 Python 3、同用户可读的 /proc 和保存登录链接的进程标准输出文件 | 已验证当前 Linux 启动方式；终端、journal 或容器启动不保证可用 |
| 主机、路径与端口 | 无个人主机或项目目录硬编码；SSH/DSH 端口均接受 1–65535。远端目录原样交给远端 DSH，不在本机拼接 | 端口、Windows 风格路径有自动化测试；非默认端口未跨平台实测 |
| DSH 客户端 | 声明 platform: web；依赖原生 sidebar、layout、sessions 和 Gateway 服务 | 当前 Windows Desktop 承载的 Web 页面可用；其他 Desktop 载入方式不能据此保证 |

其他边界：仅支持 SSH 密钥/Agent，SSH 服务必须允许 TCP 转发；导入只枚举用户 ~/.ssh/config 中的具体别名，通配符与 Match 条件不能当作完整自动发现。手动登录链接不落盘，因此主后端重启后需要重新提供。每帧/响应上限 4 MiB、最多 16 个连接，以及尚未转发的审批、提问、第三方卡片，都会限制“完整原生体验”。

公开发布前仍需在 Windows 和 macOS 主后端、Windows 和 macOS 远端分别验证连接、目录/会话操作、消息起止状态与重连；模拟平台参数测试不能替代这些实机组合。

## 接入实现

`src/index.js` 在插件生命周期内包装 `typertGateway.invoke/stream`；`native-wire.js` 对 DSH 0.1.7 Web Carrier 的 `invokeRpc/openWireStream` 作限定适配，卸载时恢复原方法。此入口不是上游公开的稳定扩展 API，升级 DSH 前必须重新核对并运行协议与浏览器回归。`native-gateway.js` 只翻译已知身份字段，不改写对话文本、路径和附件内容。`native-contract.js` 集中声明当前适配的操作。

这是对公开服务方法的运行时适配，不是上游承诺稳定的多后端中间件接口。没有覆盖 DSH 安装文件，也没有第二套对话 renderer 接管原生会话；源码中保留的早期 renderer 仅用于历史测试，不是当前界面。

设置和主页面通过 DSH 插件槽注册。原有 directoryFlow 是单占用槽，本插件不替换其现有目录选择器；远端“添加工作区”入口仅在多端管理中，原生“+”仍创建主后端工作区。

## 基础协议检查的边界

连接和重新登录时，在暂存的 SSH carrier 上读取 workspace/follow 与 session/control 的首个 baseline，校验结构并关闭探测订阅。失败则不接入，主后端保持可用。当前契约不提供这里可以依赖的 DSH 语义版本字段，所以界面明确显示“远端版本未核验”；不能把它标为与主机版本一致。基础协议检查也不能证明所有写操作都兼容。

## 更新流程

1. 记录目标 DSH 版本，检查 Host gateway、Client loader 依赖、原生会话与工作区签名。
2. 在独立 profile 加载插件，运行 `npm ci`、`npm run build`、`npm test`。
3. 实际验证连接、目录浏览、创建、原生会话、改名、归档、排序、断线、未发送草稿；变更测试只用专用会话。
4. 分别验证附件、审批及第三方卡片，不能用文本对话通过代替这些验收。
5. 记录通过和未覆盖的范围，再发布插件预览版。不要直接在运行任务的主力后端升级。

DSH 当前开发安装不监视链接源码；Host 代码更新需要检查任务状态后重载后端，刷新浏览器只能更新 Client 代码。
